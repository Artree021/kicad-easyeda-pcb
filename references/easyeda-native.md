# 嘉立创 EDA 专业版迁移与原生调整

以下是 Windows 嘉立创EDA专业版 4.1.x 的已知版本经验；新版本先核验，不假设内部接口稳定。

API 代码片段要求当前环境已建立受控连接并提供 `api` 对象，不是独立可运行程序。桥接工具或 SDK 由使用者自行安装，本包不包含第三方 `easyeda-api` SDK。依赖发现与无接口时的替代流程见[环境与证据](local-environment-and-evidence.md)。

## 受控访问与快照

- 优先现有应用/浏览器能力。若应用已经开放本机 CDP，枚举并核实目标的 URL、标题、类型，再绑定精确 target；不要选“第一个 page”，也不要把端口当永久常量。
- 定向 CDP 的 DOM/API/截图可以避免干扰用户正在使用的其他应用；不要发送桌面级输入。不同 PCB、原理图、3D 可能位于不同 iframe；每次确认活动文档。
- 本地启用调试仅绑定 loopback，不读取/输出账号令牌、cookie 或无关用户数据。不必为此安装新的浏览器或常驻工具。
- 修改前保存可恢复的原生导出，并记录当前 PCB/原理图、显示状态及待保存改动。不要把显示设置变化当几何修改，也不要覆盖用户真实编辑。
- 编辑以小批次进行，逐批保存、重读验证；接口调用超时后先确认状态，避免重复新增或重复提交。
- 目标 EDA 窗口最小化时，已有版本案例出现 CSS `leave-active` 退出动画和截图停滞。先检查目标窗口状态，不重复点击正在退出的对话框。需要恢复渲染时，仅对已核实属于 EDA 的 HWND 调用 `ShowWindowAsync(hwnd, SW_SHOWNOACTIVATE)`，操作前后比较 `GetForegroundWindow()`，确认用户前台窗口未变；不要借此使用全局激活、置顶或焦点模拟。恢复后重读 DOM/截图确认真实状态，不能把动画停滞当业务提交失败。

## 导入兼容与电气复核

原始 KiCad 保留不动；导入副本含原理图、PCB、项目配置与本地符号/封装库。

已知 KiCad 10 新网络序列化曾被导入器误解，造成看似断线/缺网络。成功路径是在副本中做**语义受限的旧式网络编码桥接**：构造编号网络表，调整焊盘/走线/区域的网络表示，保留几何；用 KiCad 再读取副本，逐项比较引脚网络、坐标、尺寸、层、线宽和圆弧中点。仅改文件版本号不能证明兼容。不要复制旧项目专用桥接脚本的哈希/版本假设直接运行。

导入后至少对比：

- 原理图：每个连接引脚的网络映射、NC 处理、全局电源名、页间连接、固定脚和网络集合。
- 元件/封装：位号、身份、板面、坐标、角度、变换后的所有铜焊盘中心/尺寸/形状/层/钻孔、编号和网络。底面镜像必须明确。
- 铜：直线端点/线宽/层/网络，圆弧的中点或扫角，过孔孔径/直径/层对/网络，铜多边形，区域定义与实际填铜。
- 机械/制造：板框闭合与尺寸、真实层序、物理厚度单位、阻焊/锡膏和丝印。
- 最后在嘉立创运行实际 ERC/DRC 并看各层。网表、几何、铺铜和视觉分别留证据。

坐标示例：该版本 KiCad 数据常为 mm、Y 向下，嘉立创原生常为 mil、Y 向上；转换为 `mil = mm / 0.0254`，Y 的符号与原点按当前数据实证。底面还有镜像及旋转，先用几个已知引脚校验，再扩大检查。

小图元丢失不可静默略过。某传感器板案例中一条约 0.002 mm 的短弧被归一化省略，实际相邻铜重叠且无断路；记录了具体网络、层和证据，结论仍是“有明确差异”，不是图元完全相同。新项目不能按该尺寸一律忽略缺弧。

## 原生编辑与铺铜保护

先查看待用 API 的函数体/文档；一些 `pcb_Layer` 层叠 API 和 `pcb_PrimitivePoured.create/modify` 只是空函数或返回 `false`。函数存在不证明可用。

**禁用整份 PCB `setDocumentSource` 作为日常修复手段**。已有失败会重解释铜对象、丢失已填充的 `POURED` 缓存，甚至让表面不变的工程产生大量问题。层厚等内容通过原生图层管理器或已验证单项操作修改，导出检查。

`POUR` 是区域定义、`POURED` 是已填充铜，两者都要检查；`FILL` 可包含局部铜/泪滴。模型和显示修改后，除允许变化的字段外，比较实际数据保持一致。若确实修改走线，需要在该软件中正确重新填铜并验证，不能保留旧填铜当最终。

`POURED.pourFill.path` 的缓存坐标与 COMPONENT/POUR 曾出现不同量级；不能给所有原生对象统一套同一单位换算。先核实各记录的语义，若未掌握缓存解析，只能确认其存在、关联和非空，不能据此声称铜边界等价。

重铺铜后的连通性报错要查整个连接分组。报错列表可能列出同一孤立网络分组中的代表对象：某个被标记焊盘与过孔重合，并不能据此把报错判为误报。分别检查区域、热焊盘辐条、走线、焊盘与跨层过孔组成的铜连接图。此版本 `POURED` 同时包含 `fill:true` 的带孔多边形和 `fill:false` 的带线宽热焊盘辐条，遗漏后者会制造假断路。重新计算飞线或重新打开文档不一定解决真实孤岛。

已验证的修复案例是沿原 KiCad 地铜逐根补充短接地线，连接芯片地脚至裸露地焊盘；两端均需要实际几何与间距检查，并在两软件重铺铜、DRC 与导出后验证。不能把这个案例扩展为无差别补地线或关闭连通性检查。局部焊盘改为直连也不保证孤岛能连到主地网。

单独修改元件内的焊盘可能建立新的本地封装。比对时优先使用实际 `Footprint` 属性指向的文档；该文档不存在时才回退 `FootprintName`，否则会误拿旧库焊盘验证。焊盘 API getter 在此版本会舍入到 0.1 mil，不能拿这些回读值无损覆写全部几何；原生属性面板修改单项后也需重新导出比对。导入后的局部直连设置要逐项核实，不能假定与源软件一致。

### 修改过孔孔径的精度陷阱

本版本 `pcb_PrimitiveVia.modify` 内部读取的直径可能已经舍入。实测只要求修改孔径时，原生 `viaDiameter = 17.7165 mil` 的铜盘曾意外变为 `17.8 mil`。先保存并读取精确原生记录，确认当前状态与快照一致；调用时同时传入目标 `holeDiameter` 和快照的精确铜盘直径，API 参数名为 `diameter`，而原生字段名为 `viaDiameter`：

```javascript
await api.pcb_PrimitiveVia.modify(viaId, {
  holeDiameter: targetHoleInVerifiedUnits,
  diameter: nativeBefore.viaDiameter
});
```

先单个试改并导出核对，再批量应用同一受限操作。保存后逐个比较：只允许目标孔径变化，铜盘直径、位置、网络、层对和其他属性均须保持。不要用舍入 getter 的数值恢复原几何；也不要凭 DRC 为零就认定未发生尺寸漂移。

### 保存/重填后的受限差异比较

编辑器可能把经过过孔中心的直线拆成两段。案例中三条旧线变为六条新线；只在逐对证明下列条件后，才在**比较副本的内存中**合并，不重写原生文件、不忽略全部 `LINE` 差异：

- 网络、层、线宽以及锁定/分组/分区等属性一致；没有剩余未配对的新旧线。
- 精确共线，两个子区间首尾相接、没有间隙或重叠超出原段，区间并集与原段完全相等。
- 已验证案例只涉及水平/垂直线，可用原始十进制坐标的 `Decimal` 比较端点和区间；斜线需另证，不能直接推广同一坐标判据。

重新填铜会生成新的内部缓存 ID，也可能产生微小浮点变化。已验证案例保持字典键集、列表长度/次序、区域关联及其他内容相等，只放行 `pourFill` 下的内部 `id` 变化，以及其 `path` 数值中逐项记录的浮点差异；最大实测差约 `4.21e-12`（原始存储标量，不能擅自标成 mm）。该次检查使用的 `1e-8` 上界只属于这份证据，不能升格为任意铜几何可忽略的公差。

保存前后原生文件、哈希、逐缓存差异数量/最大值、允许字段路径和重填后的实际 DRC 一并保留。源/目标单位、结构或边界变化不明时停止归一化并调查；不能因名称是“缓存”就忽略整块填铜。记录头的 `ticket` 重排也只单独排除该字段，其他头字段继续比较。

保存有时插入重复的连续多边形顶点。只有确认精确相同、产生零长度边时才能单独归一化；不准任意舍入、简化多边形或忽略网络/层差异来“获得相等”。摘要不同应展开查看原因。

## 层叠单位

观察 UI 当前单位，并检查导出中的 `LAYER_PHYS` 值。该版本存储厚度为 mil；误把 1.546 mm 的数值原样存入，会显示约 0.039 mm。逐层核对铜/介质/阻焊的实际换算，并同时检查 3D 总厚度。

工程叠层模型总和、含阻焊可视厚度和下单标称成品厚度可能不同，分别标注。厂商默认 1.6 mm 不等于强制下单定制 1.546 mm；未经确认不指定收费的特殊叠层。

## 原理图表达

选择目标页，通过原生单图元方式整理线、标签、文本和图框。全局网标能建立电气连接，但不能替代可读的局部连线；同样，线看似相接也可能未吸附到引脚。修复后再次导出逐引脚网表，确保仅表达改善时电气图不变。

展示时 fit 页面、关闭不必要的底部库/面板；布局预览可隐藏丝印、fab 和元件文本。只有用户要查看接口标识时再显示相关层，不要隐藏待审查的铜。

## 3D 模型与连接器

导入器可能只带模型库 UUID 而没有模型 UUID，表现为裸板。检查元件 `model3D` 与属性，不能因此推断二维封装丢失。

已验证的局部绑定形态（变量从当前工程/系统库查得）：

```javascript
const c = await api.pcb_PrimitiveComponent.get(componentId);
await api.pcb_PrimitiveComponent.modify(componentId, {
  otherProperty: {
    ...c.otherProperty,
    '3D Model': modelUuid,
    '3D Model Title': modelTitle,
    '3D Model Transform': verifiedTransform
  }
});
```

保留其他属性，重新读取确认模型 UUID。不要为绑定模型替换已核验的二维封装。该版本 transform 为 `[sx,sy,sz,rz,rx,ry,ox,oy,oz]`；前三项沿用库的尺寸/缩放参数约定，角度为度、偏移按 mil。先从真实库变换与本地解析器确认语义，不能套用普通三维矩阵顺序。

可以用 `lib_Device.getByLcscIds` 获取精确型号及模型。无精确模型时，同封装通用外观可用于显示，但保留 BOM、明确视觉近似，不能用它证明机械尺寸或采购型号。

连接器尤其要注意：库编号可能与自定义封装相反。机械匹配依据尾脚排、两侧固定脚、本体中心和开口面；按编号拟合导致 180° 错转时修正模型，不调换实际针号。顶视检查信号/固定脚落点，底视检查底面变换，侧视检查插口朝外与板厚。等待模型加载完成后再截图；加载中的裸板不能作为失败结论。

保存原生工程并导出，比较所有二维位置、封装身份、针号、网络、铜及铺铜。若只改模型，仅允许三个模型属性及确证无电气影响的元数据变化。**模型正确仍不替代代贴平台的贴装预览核验。**
