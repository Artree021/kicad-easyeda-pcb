# 迁移与原生编辑

用于 KiCad 与嘉立创EDA之间的工程转换、器件关联、层叠及模型调整。历史经验主要来自嘉立创EDA专业版 4.1.x；文件结构、API、精度和导入能力均先在当前版本小样本验证。不要为了检查旧经验重跑整板操作。

## 先对齐规则，再转换

在布局和布线前，将目标制造服务的能力、装配条件和本项目设计目标映射到两端规则；来源与区分方法见[规则与来源](rules-and-sources.md)。迁移前冻结当前规则快照，导入后确认规则实际生效，包括：

- 电气铜间距、线宽、孔径与环宽、铜到板边，以及各网络类别的覆盖关系。
- 元件实体、焊盘、通孔与贴片器件的空间关系。铜到铜间距不替代实体、锡包、工具和连接器插拔空间。
- 阻焊、锡膏和丝印；同网络对象是否参与检查、哪些对象或层被排除。
- 规则优先级、错误/警告级别、忽略项、豁免项、运行选项及输出截断情况。

KiCad 通过而目标软件报错时，按对象和实际几何逐项归类：**源设计问题、转换改变、规则或检查口径差异**。不能直接认定某个软件更宽松，也不能为得到相同报错数而放宽规则。允许有理由的例外，但应注明适用对象、证据、工艺依赖和是否已在工程中持久保存；写了说明不等于原生豁免已生效。

## 选择转换路线

1. 确认源软件的版本、原理图/PCB、库和未保存改动，保存可恢复快照。本阶段只指定一个权威工程，其他副本注明用途与是否过期。
2. 用代表性副本验证支持的格式。样本包含层次页、多单元或隐藏脚、自定义封装、底面器件和圆弧；单个库转换成功不代表整工程可往返。
3. 优先使用当前版本支持且已核对的导入/导出。没有完整转换证据时，可保留原生工作流；需要重建时明确写“重建”，并逐引脚比对，不能声称无损导入。
4. 保存原始工程和转换副本，完整携带项目规则及本地符号/封装。仅复制板文件可能加载默认规则；事后补配置不能证明之前填铜用过正确规则。
5. 导入后按[迁移核对记录](../templates/migration-check.md)验证，再继续原生编辑。

历史上 KiCad 的新网络编码曾被导入器误解。限定成功做法是在副本中桥接网络序列化，再由 KiCad 重读，比较引脚网络和全部受影响几何。只改版本号、套用旧项目脚本或得到同样的对象数量，都不能证明兼容。桥接只在当前差异确实需要时使用。

## 对比语义与实际输出

| 对象 | 必须核对的内容 |
| --- | --- |
| 原理图 | 实例/单元/引脚的完整清单、网络成员、NC、隐藏脚、电源名和页间连接。先证明两端导出覆盖完整，避免两边同时漏脚却得到零差异。 |
| 封装 | 位号与身份、板面、位置和角度；变换后的焊盘中心、尺寸、形状、层、钻孔、编号和网络。同号多物理焊盘保留多重集。 |
| 铜 | 线端点/宽度/网络/层，圆弧中点或扫角，过孔孔径/铜盘/层对，区域定义及实际填铜。还要检查扣除孔后的实际连续铜和通道。 |
| 制造 | 板框及槽、层序/物理厚度、阻焊、锡膏、丝印和钻孔。以实际导出核对，不能只看编辑器显示。 |

原点、轴方向、单位、底面镜像和旋转先用已知引脚验证。毫米与 mil 的换算关系固定，原生字段采用哪种单位并不固定；同一文件中的元件坐标和填铜缓存也可能采用不同尺度。不能给所有记录套同一转换。

归档文件、运行时 API 导出和界面对象可能采用不同表示。先在同种表示下比较前后结果，再建立经过验证的跨表示映射。对象总数不同不自动表示丢失；总数相同也不表示等价。

对差异采用有限、可解释的归一化：

- 保存可能把一条线分为数段。仅在网络、层、线宽和其他属性一致，精确共线且区间并集相等时，在比较器内合并；不改工程来迎合比较器。
- 连续顶点精确重复产生零长边时，可单独记录并归一化。不能任意舍入坐标或简化多边形以取得“相等”。
- 内部缓存标识、记录顺序或微小浮点变化，按具体字段及已证单位解释；历史容差不是新工程通用阈值。不能忽略整块缓存或全部某类图元。
- 极短圆弧被省略也应记录。需证明实际连接、间距和形状影响，不能按尺寸一律豁免。
- 对真实铜差异注明区域、原因、功能影响与接受范围。有限接受不等于逐点等价，也不等于负载能力已实测。

## 原生编辑的最小闭环

确认目标文档及用户是否正在编辑。优先应用 API 或定向页面能力；无法避免占用前台键鼠时，先协调操作时段。不要依据“已经连接”选择第一个页面，也不固定端口、句柄或坐标。

每批操作执行：**快照 → 代表性单件试改 → 保存 → 重读或重载 → 导出对比 → 再扩批**。先规定允许变化的字段及必须保持的对象。单件试验应覆盖不同风险类别，例如普通焊盘、多边形焊盘、泪滴、底面和自定义封装；一个普通器件通过不能代表全部类别。

- 小试丢失表达式、说明、网络或几何时立即停批；不能以“核心还在”继续扩大同步。
- 逐批保存并核对实际持久数量。白屏、断连或超时后先保护现场、检查最后保存状态，再正常重开同一工程；不要重复整批提交。
- 返回成功但读回为空，先缩小复现、确认文档/保存时序及 API 实现。一次即时导出可能尚未更新，需要有界重读；不能无限重试写入。
- 用户开始修改后停止写入，接手其新保存版。恢复只针对可证明由本次操作造成的差异；不以全局撤销或旧包覆盖破坏用户后续修改。
- 聚合百分比、空面板和超时不是完成回执。确认真实任务/层的状态，能取回原任务结果时不另起同类长任务。

## 已知工具陷阱

以下为历史实测条件，不表示所有版本都存在。先在当前版本验证最小样本，不把失败接口当推荐写法。

| 触发 | 现象与处理 |
| --- | --- |
| 以整份 PCB `sys_FileManager.setDocumentSource` 修层叠或外观 | 曾重解释铜对象并清掉填铜缓存。**不得作为常规修复手段**；使用原生界面或已验证的单对象操作，保存后比较实际导出。 |
| 层叠或铺铜 API 存在 | 部分历史接口是空实现或固定返回 `false`。先看当前文档/实现，再试单件并读回；函数存在不代表可用。 |
| 仅修改过孔孔径 | getter 的舍入曾使铜盘直径一同改变。读取精确原生值，明确保留铜盘；历史 API 参数为 `diameter`，原生字段为 `viaDiameter`，须核实当前语义。逐孔对比位置、孔径、铜盘、网络及层对。 |
| 用焊盘 getter 回写完整几何 | 历史 getter 曾舍入到 0.1 mil。不能将显示/舍入值当无损源；单项修改后导出比对。 |
| 修改元件内焊盘后验证 | 可能产生本地封装副本。优先解析实际 `Footprint` 指向的对象，不能只按旧 `FootprintName` 取库几何。 |
| 空或旧填铜缓存 | `POUR` 区域定义、`POURED` 实际填铜、`FILL` 局部铜/泪滴应分别识别。不了解缓存解析时只报告已知范围，不能据此断言断铜或等价。 |
| 重铺后连通性报错 | 检查整个连接分组、热焊盘辐条和跨层孔；历史记录中有带孔多边形及带线宽辐条两类填铜，漏解析其中一类会误报。焊盘与某孔重合不证明已接主网。 |
| 最小化、白屏或动画停滞 | 先检查窗口可见性、目标文档与渲染状态。仅恢复已识别窗口并验证是否影响前台，不能连续盲点或把界面未刷新当业务失败。 |

确有断口时，先定位缺失连接与目标层通道，再有限补桥；修改后检查相邻层、孔、间距和实际输出。改成直连、重算飞线或无差别加地线都不能代替连接验证。

## 器件关联、模型与层叠

**关联器件身份不等于替换封装。** 精确型号匹配后，保护已有焊盘、针号、网络、位置和板面。替代料、封装名不同、采购字段缺失、SMT 库不支持、仅缺 3D 分别处理。优先局部更新真实器件关联，避免一键标准化覆盖已核验封装。

模型绑定可能触发二维重新生成或泪滴变化，元数据操作也要核对副作用。比较所有焊盘、线/弧/过孔、铜区、实际填铜、泪滴、丝印和用户新改动；不是只核对模型数量。模型异常先停止写入，再受限恢复和复查。

连接器模型按信号脚排、固定脚、本体及开口共同对齐。库针号映射相反时修模型，不能反改已核验的二维针号。顶/底/侧视分别看落脚、底面变换、插口朝外和高度。只有通用外观时标为近似模型；3D 不能证明采购型号或 SMT 贴装方向。

模型属性/变换顺序从当前文档和已知模型验证，保留其他属性，不照搬历史变换数组。等待实际加载并保存后重读，避免将加载中的裸板当模型缺失。

层叠逐层确认铜、介质、阻焊和单位，再核总厚度。工程模型厚度、含阻焊的显示厚度和订单标称成品厚度可以不同，应分别记录。不要为让数值相等而擅自选收费定制工艺。

## 原理图同步

整理表达时保留电气语义；全局网标不替代可读连线，视觉相接也不证明吸附引脚。反向同步前查看变更预览，逐项区分身份、描述、封装与网络修改，先小试保护继承表达式和说明。

点击“应用”、变更预览条目数或 PCB 的零 DRC 均不能证明原理图已保存。同步后保存所有受影响页，重新读取完整引脚网络及属性，再运行对应 ERC/一致性检查。未证持久结果写“待验证”，不能用后续其他检查补认完成。
