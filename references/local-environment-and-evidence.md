# 环境发现与验证证据

本包提供通用流程与只读检查脚本，不附带原项目、私人证据、软件安装目录或第三方 SDK。先识别当前环境，再选择可执行的步骤。

## 发现现有工具

1. 确认用户的工程目录、权威设计文件与允许修改的范围，记录当前版本和已有未保存编辑。不要扫描无关个人目录寻找项目。
2. 从系统 PATH、软件设置或用户指定位置发现 `kicad-cli` 与 Python。Windows 可用 `Get-Command kicad-cli, python, py -ErrorAction SilentlyContinue`，macOS/Linux 可用 `command -v kicad-cli python3`；发现结果仅作本地执行定位，分享报告只记录工具名和版本。
3. 用版本命令确认真正可运行的程序。裸 `python` 在某些 Windows 环境可能只是商店入口；不把命令存在当作 Python 已安装。
4. 包内 `inspect_epro2.py` 只需 Python 3.10+ 标准库。需要读取 KiCad 板对象时，另在候选解释器里验证 `import pcbnew`，普通 Python 与 KiCad 二进制扩展不一定兼容；几何导出和其他分析可以分进程完成。
5. 通过已有应用能力确认嘉立创EDA的版本、目标页面和文档。若使用 CDP，枚举并匹配准确目标，不固定端口或选择第一个页面；调试连接只绑定本机回环地址。
6. 文件及工具间文本统一使用 UTF-8。PowerShell 管道遇到非 ASCII 文本时先核查实际传输编码；中文选择器无匹配不直接证明页面结构变化。

## 可选的嘉立创EDA API 依赖

纯 KiCad 设计审查与包内离线检查脚本不依赖第三方桥接工具。执行嘉立创EDA原生自动化时，可使用当前环境已有且获授权的官方扩展/API 通道，或自行安装兼容的 `easyeda-api` skill/桥接工具。

本包**不包含 `easyeda-api` 的 SDK、扩展源码或完整 API 手册**。其许可与分发条件未核实，不随本包重新分发。使用者应从其原维护来源获取，审查许可和安装说明，并验证客户端/桥接/API 版本兼容；不能把包内示例当作该依赖已经可用。

若环境没有可用桥接，继续完成可离线做的 KiCad、制造文件和原生导出审查，清楚列出需要用户在编辑器完成的操作。不要编造 API 返回值，不要为适配示例而读取浏览器账号令牌或 cookie。

## 最小证据结构

在当前工程的受控工作目录中维护以下内容；这些是建议记录类型，不是本包附带的项目文件：

| 记录 | 应包含的内容 |
| --- | --- |
| 设计约束 | 功能、尺寸、供电、层数、连接器、采样/通信目标及用户偏好 |
| 来源与版本 | 料号、封装及原厂资料版本；设计与制造文件的相对名和 SHA256 |
| 路径审查 | 端点、分支、层/宽、换层、参考面、实际观察、对应版本 |
| 电气/几何检查 | 检查命令或工具版本、真实退出状态、违规数量、关闭的规则与未测项 |
| 迁移差异 | 逐引脚网络、变换后的几何、单位、模型及铺铜；每项允许差异的依据 |
| 制造与装配 | 同版本 Gerber/钻孔/BOM/CPL、原点与板面约定、最终贴装预览及待确认工艺 |

证据采用相对名或末级文件名；若必须保存本机定位，将其放在不分发的本地配置中。工程导出和截图仍可能含订单号、账号、设备标识、文件路径或私有料号，分享前单独检查。

## 避免历史方案回退

- 项目生成脚本可能在导入模块时就重写文件；先读顶层代码，不把 `import` 当作无副作用读取。
- 已弃用的布局、层叠、拼板或自动布线方案不能仅因仍有脚本就覆盖当前源。
- 单位换算、连接器针号与模型方向在当前版本重新验证；不继承旧工程 ID、坐标或容差。
- API 成功、保存成功、重铺铜、检查通过与实物验证分别记录；实际重读结果优先于接口返回。

关于原生数据的具体失效条件见[嘉立创EDA原生工作流](easyeda-native.md)；关于制造和外部提交的边界见[制造与贴装交付](manufacturing-handoff.md)。
